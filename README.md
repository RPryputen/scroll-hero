# Hero block с 3D-ядром и анимацией по прокрутке

Тёмный «премиальный» hero-блок для сайта об автоматизации бизнеса с ИИ.
Вся анимация привязана к прокрутке, без внешних библиотек и шрифтов —
достаточно открыть `index.html` в браузере.

## Структура

```
├─ index.html          # разметка hero + секции-заполнители для теста скролла
├─ css/style.css       # стили и вся раскадровка анимации через var(--p) / var(--e)
└─ js/
   ├─ constellation.js # canvas-фон: точки и линии-«созвездия»
   ├─ core.js          # 3D-ядро: икосаэдр на canvas 2D + раскадровка
   └─ main.js          # прогресс скролла → CSS-переменные, параллакс, reveal
```

## Главный приём: три плана по глубине

```
z 4   АВТОМАТИЗАЦИЯ БИЗНЕСА С ИИ:   ← читаемый текст, уезжает вверх
z 3          ◆ 3D-ЯДРО ◆            ← canvas, перекрывает слово-подложку
z 2      A U T O M A T I O N        ← гигантское слово, его перекрывает ядро
z 4   САЙТЫ, ТГ-БОТЫ, CRM.          ← читаемый текст, уезжает вниз
```

Ядро физически перекрывает слово-подложку — это и создаёт ощущение реального
объёма. При прокрутке верхняя и нижняя строки расходятся как шторы, открывая
объект.

Важно, что **обе строки заголовка лежат перед ядром**: объект непрозрачный,
и строка позади него стала бы нечитаемой. Роль «перекрываемого» слоя играет
декоративное слово-подложка, читаемости оно не мешает.

В потоке заголовка между строками стоит пустой `.line-gap` — в нём и живёт
ядро, по его центру `main.js` вычисляет `--cy`. Поэтому объект остаётся
привязанным к тексту на любой ширине экрана.

Чтобы слои сработали, `.hero__inner` обязан иметь `z-index: auto`: иначе он
создаст свой контекст наложения и строки не смогут «расслоиться» вокруг
canvas-а, лежащего вне его.

## 3D-ядро (`js/core.js`)

Икосаэдр (12 вершин, 20 граней) на обычном canvas 2D с честной 3D-математикой:

- поворот по осям Y/X, перспективная проекция;
- сортировка граней по глубине (алгоритм художника);
- плоское затенение двумя источниками: фиолетовый ключевой + синий контровой;
- светящееся ядро внутри, лучи от него к разлетевшимся граням;
- три кольца орбитальных частиц с разным наклоном и скоростью.

Ничего не грузится с диска — ни картинок, ни секвенций кадров.

## Раскадровка

`.hero-scene` высотой `340vh` задаёт длину анимации, сам `.hero` залипает
на `100vh` через `position: sticky`. `js/main.js` считает прогресс прокрутки
внутри сцены (`0…1`), сглаживает через lerp и пишет в CSS-переменные.
Раскадровку задаёт единственная функция `story()` в `core.js` — её читают
и canvas, и CSS (через `--e` / `--out`), поэтому они не расходятся.

| Прогресс | Что происходит |
| --- | --- |
| 0.00 – 0.15 | ядро медленно вращается, текст на месте |
| 0.15 – 0.52 | строки расходятся вверх/вниз, ядро раскрывается на грани |
| 0.38 – 0.74 | грани разлетелись, зажигаются подписи модулей, ядро горит |
| 0.74 – 0.96 | обратная сборка |
| 0.82 – 1.00 | всё схлопывается в точку, сверху наезжает первая секция |

Дополнительно: параллакс от курсора (`--mx` / `--my`), полоска прогресса
страницы, сжимающийся header, появление секций по `IntersectionObserver`.

## Настройка

| Что менять | Где |
| --- | --- |
| Тайминги раскадровки | функция `story()` в `js/core.js` |
| Скорость прокрутки | высота `.hero-scene` в `css/style.css` |
| «Вязкость» движения | константа `EASE` в `js/main.js` |
| Размер ядра | множители в `var R = Math.min(w * .30, h * .25)` |
| Дальность разлёта граней | константа `PUSH` в `js/core.js` |
| Сила перспективы | `PERSP` — должен с запасом превышать радиус внешнего кольца, иначе ближние точки улетают за экран |
| Подписи модулей | `--x` / `--y` в разметке `.module`, масштаб — `--ms` в медиазапросах |
| Плотность фона | `LINK_DIST` и `count` в `js/constellation.js` |

Учтён `prefers-reduced-motion`: при включённой настройке анимации отключаются,
3D-ядро и подписи скрываются, hero становится обычным экраном на `100vh`.

Икосаэдр легко заменить на другую фигуру: достаточно подменить массивы
`VERTS` / `FACES` в `core.js`, остальная логика (свет, сортировка, разлёт)
не изменится.
